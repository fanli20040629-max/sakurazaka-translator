# 模块地图与接入边界

本包路径均相对 core_modules。正式接入后，src/com/fanli/sakurazakatranslator/domain 移至主工程 app/src/main/java 的同包目录。不要为了让目录看起来完整，预建没有实现的 OCR、overlay、deepseek 空类。

## 已实现文件

| 文件（domain/ 下） | 输入/输出与职责 | 明确限制 |
|---|---|---|
| model/Bounds.java | 非空屏幕绝对像素矩形，包含关系 | 局部截图坐标要由适配层换算；越屏先裁剪 |
| model/PageToken.java | 包名、窗口、页面代次、采集时间组成身份 | 不自行监听 Android；相等不表示页面现在仍有效 |
| model/TextFragment.java | 原文、来源、角色、边界、遍历序号、置信度、选择状态 | 不自动判断哪段是正文；-1 表示未知置信度 |
| model/ChatMessage.java | 消息/人物/时间、片段、图片区域和已确认边界标志 | 没有 Bitmap；没有复制一份可变 UI 状态 |
| assembly/MessageAssembler.java | 已确认单条消息 → 排序正文片段和 sourceText | 不实现整屏分组/消息边界检测 |
| style/StyleProfile.java | 带版本的通用规则、Blog/MSG 说明、词典和示例 | 不预置真实偶像档案，不自动分析 Blog |
| translation/SymbolProtector.java | 原文与显式保护片段 → 符号序列；对比译文 | 不修补、不翻译、不识别图片，也不是完整 Unicode 分类库 |
| translation/TranslationRequest.java | 请求/页面/消息/人物绑定、正文、文风、保护片段 | 固定 zh-Hans；不承载密钥、整屏、Blog 全文 |
| translation/TranslationResult.java | 译文、请求绑定、提供商/模型、风格版本、待确认标志 | 不提供虚假的语义准确率 |
| translation/TranslationProvider.java | 异步文本请求 → CompletionStage 结果 | 接口无真实网络实现；取消 Stage 不保证取消 HTTP |
| translation/TranslationValidator.java | 请求+结果 → 问题列表 | 检查绑定/非空/符号；不判断中文语义或当前屏幕 |

## 简单的数据流

Android 节点/局部 OCR → 已确认的 ChatMessage → MessageAssembler → TranslationRequest → Provider → TranslationResult → TranslationValidator → 总协调器确认页面仍有效 → 显示层。

总协调器包围整个过程，管理生命周期；不是数据流中某个模型的布尔字段。最终显示层只显示结果，不直接请求网络。

## 消息整理的精确规则

1. boundaryConfirmed=false 时拒绝整理，返回异常，不猜边界。
2. 同 ID 且所有数据相同只保留一次；同 ID 数据不同直接报冲突。
3. 仅 selected=true、Role.BODY、非空、完全处于消息 bounds 的片段参与翻译。
4. 按 top、left、整数 traversalIndex 排序。同坐标同序号保持输入顺序；真实输入若无顺序依据应上游标记待确认。
5. 不按字符串 ID 排序，不按用户勾选顺序，不按全文全局去重。
6. 不修改 rawText 的空白、符号或内部换行；片段之间用一个换行连接。上游应提供逻辑行/块，不能把逐字 OCR 直接传进来，否则会出现多余换行。
7. 边缘消息不完整时不要强行裁剪为“已确认整条消息”。已选图片/语音控件也不会自动变成正文。

同位置不同来源的重复文字本包不会自动去重，因为 text/description/OCR 可能有不同含义。节点适配层需保留来源证据并消除已证明的重复；不靠猜测消除。

## 符号保护的精确规则

- 自动记录波浪号、爱心等常见符号、常见 Emoji 码点、ZWJ、变体选择符、肤色/旗帜/键帽组合成分、感叹问号及换行。
- 对比整个受保护序列，所以删除重复爱心、交换波浪号与爱心、改变肤色、改变键帽数字都应失败。
- 比较时 CRLF/CR 与 LF 等价；原文存储不改。
- 不改变普通日文句号/逗号为固定格式；译文可自然使用中文标点。
- 颜文字/其他装饰片段可由上游给出 exact literal；较长匹配优先。空片段、原文不存在的片段拒绝配置。
- 保护范围是保守区间，不保证覆盖每个 Unicode 新增符号，也可能多保护装饰符。后续用实际失败样例扩充，必要时使用可核验的 Unicode 数据表。
- 只能校验已识别的文字。若 OCR 把 💗 看成一个汉字，本模块不知道原图里是爱心，需要改善识别或经确认使用视觉模型。
- 保证符号相互次序不保证它们与每个词的语义位置一致，也不保证译文含义正确。不能自动补回符号后假装通过。

## 风格与 API 扩展

人物由稳定 ID 绑定，显示名可以改变；配置版本更新必须推进 version。Blog 和 MSG 分开，不让 Blog 正式语气覆盖 MSG。两位人物使用两份配置；增加第三位只新增档案，不改核心类。用户偏好如何持久化、Blog 如何分析都留在后续配置模块。

Provider 接口不固化 DeepSeek，后续也可使用用户自带 Key 或受控后端。API Key 在 Android 侧应使用 Keystore 管理的加密密钥保护本地密文，不是把 API Key 当普通字符串直接塞进源码或声称 APK 内共享密钥绝对安全。分享给别人也可让每个人填自己的 Key，不必第一版就建设账号服务器。

传输失败以异常完成异步结果；仅在后台实现实际网络。协调器统一超时/取消/重试。提供商内部必须校验 JSON 结构、服务器回传 messageId 和 HTTP 状态；模型回传内容只当数据，不能当系统命令。结构校验通过之后再做本地符号校验。

## 旧代码如何对应

| 审核快照文件 | 保留与迁移方式 |
|---|---|
| TranslatorAccessibilityService.java | 保留 Android 生命周期入口；逐步抽出读取、OCR、显示；不规定硬性行数 |
| CaptureCoordinator.java | 核对后作为唯一总协调器迁移起点；不能因为该类测试通过就声称生产已接入 |
| ProbeLogic.java | 移除生产中重复的 RequestGate 使用；资源租约/纯工具按调用关系保留 |
| ProbeModels.java | 旧模型先保留，入口适配到新模型；不要批量改所有 import |
| TextAssembly.java | 旧诊断格式和候选分类先保留；逐条接入 MessageAssembler，不能直接用其 BODY 候选当已确认正文 |
| MainActivity / ProbePreferences | 保留设置与调试入口；API/风格配置后续逐步扩展 |

文件拆分按职责和独立测试价值决定。无需给每个类再造一个接口，无需一次性建满上次讨论的全部目录。可以一次修改一个完整功能涉及的多个文件，但不能同时重做几个独立子系统。
