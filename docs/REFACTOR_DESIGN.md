# 渐进式重构设计

> 2026-09-16 进度见 [REFACTOR_PLAN](REFACTOR_PLAN.md)。下文是设计目标，不是所有分层已经落地：目前实现位于 capture 和 domain；overlay / translation 尚未建立独立包。OCR 片段未分组为聊天消息。

## 目标

把当前服务整理成易读、可测试、可继续接入翻译的结构，同时保留现有浮窗、节点读取、截图和 OCR 行为。

## 结构

- `capture`：窗口、节点、截图和 OCR 协调。
- `overlay`：结果展示与候选选择边界。
- `domain`：不依赖 Android 的消息、风格、翻译请求/结果和校验模型。
- `translation`：翻译接口与本地占位实现，本阶段不发送网络请求。

## 数据流

窗口事件 → 页面身份确认 → 节点/OCR 候选 → 用户确认 → `ChatMessage` → `TranslationRequest` → Provider → 校验后的 `TranslationResult`。

生产界面只对用户勾选的 OCR 候选生成本地请求；节点仍为只读分区。请求工厂本身不能证明授权，后续网络层必须绑定页面身份和显式操作。原始提取文本保留；符号保护、译文校验和失败回退仍是后续目标，不能用当前数量校验冒充实现。

## 约束

- 不新增网络权限，不保存 API Key，不上传截图。
- 不在没有真机证据前自动猜测聊天消息边界。
- 每个纯逻辑模块都有可执行的 Java 自测。
