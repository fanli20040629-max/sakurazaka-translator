# 翻译卡与长消息补取：实施和今晚验收

用户已在聊天中确定第二种卡片，并授权本轮实现后统一真机测试。本文件替代复盘方案第 9 节的待选建议；旧气泡旁全文保留源码作为历史实验，不再作为默认阅读入口。

## 本轮范围与约束

- 原聊天页面上的单个阅读窗口：上下停靠、上一条/下一条、原文切换、滚动、展开、收起恢复、重新取字。结果只驻留内存。
- 复用现有 TranslationRequest / TranslationResult / TranslationRunner / DeepSeekProvider；换显示不发请求。默认显式确认发送；可在设置页主动勾选并保存“快捷翻译”授权，之后一次主动取字点击可发送无警告且全部正文候选都获推荐的节点文字。有未推荐 BODY/UNKNOWN、OCR 混选、截断警告、数量/长度超限或长文草稿时仍确认。不能只因推荐选择或 OCR 到达直接扣费。
- 长消息读取保留节点提供的原始全文，不按屏幕高度裁掉字符串；几何越界仅提示可能截断，不宣称完整。正文自动推荐保守执行，OCR 不自动选，用户取消后不因 OCR 到达而重新勾上。
- 多屏补取只在用户主动开启时进行：每次手动滚动、取字、选择同一条消息片段、确认加入；不自动滚动、不自动补字、不混合不同来源；不确定的重叠拒绝合并。最后确认首尾完整，再走原有发送确认。
- Java 17，minSdk 34，compile/targetSdk 36；不增加第三方依赖。保留旧签名及设置，不自动卸载。
- 滚动令坐标失效。已成功译文可作为“上次识别”收起保存；切换应用、窗口、锁屏清理。跨屏草稿不能作为实时消息，不以旧坐标定位。
- 真机、真实 API、Windows Android 构建必须分别记录证据；本机逻辑测试不代替上述验收。
- 当前追加成员识别：优先读取有标题结构依据的聊天页姓名，使用本地档案的显示名/别名精确匹配。正文中提到的人名、列表里的同名文本、模糊昵称不会触发切换；未知、冲突或标题缺失时暂停快捷发送，允许仅本次手动确认。可靠换人会清除旧草稿和阅读卡，迟到译文不能显示到新成员。

## 实施任务

1. 输入策略与补取模型（纯 Java）：新增 BodySelectionPolicy、LongMessageDraft；测试标题排除、来源/窗口隔离、无重叠拒绝、重复页幂等、符号/重复词保留、长度上限和清理。
2. 阅读状态与窗口：新增 ReadingSession、TranslationReadingOverlay；测试拒绝未接受/错 ID 结果、页内导航边界、原文切换、过期标记及清理。Android 窗口使用实际系统可用区域，上下固定停靠；正常尺寸按钮固定、正文单独滚动，小屏/大字体空间不足时整卡滚动保证按钮可达。
3. 服务和选择页集成：只在节点结果打开时推荐一次；显示已选状态；发送成功自动打开阅读卡。自己的浮窗事件不作原页面变化；不把未知应用窗口误当允许的目标。手动补取复用候选选择，清楚显示待补全与发送范围。
4. 回归与交接：版本升至 8 / 0.7.0-reading-card-trial，同步验证脚本；运行桌面测试、可用 Android 类型编译、协议 JUnit、diff 检查；更新交接入口和执行记录。
5. 成员识别与风格隔离：新增 `MemberResolver`、`MemberSession`；设置支持每档案姓名和别名，快捷翻译要求可靠自动匹配。成员识别是本地规则，不上传标题或截图。

## 今晚 Windows 执行顺序

### 1. 接收代码和确认身份

本轮先完成本地修改，不能因为本文件出现就认定已推送 GitHub。只有确认分支上传后，另一台电脑才能从 `origin/codex/chat-bubble-layout` 获取。先保存原机未提交修改，不覆盖 `local.properties`、`debug.keystore`、SDK/JDK 或缓存，不使用 reset --hard、clean、自动卸载。

在真实工程目录核对 `git status --short`、`git branch --show-current`、`git log -1 --oneline`。工作区干净且本地已在交付分支时，执行 `git fetch origin` 后 `git merge --ff-only origin/codex/chat-bubble-layout`。若不能快进，先记录差异并解决，不覆盖。若尚无本地分支，先检查远程确实存在，再 `git switch --track origin/codex/chat-bubble-layout`。若远程仍为版本 7，停止以新版名义测试，先接收本轮代码。

必须同时存在 `ReadingSession.java`、`TranslationReadingOverlay.java`、`ReadingDemo.java`、`BodySelectionPolicy.java`、`domain/LongMessageDraft.java` 及 3 个新增自测，版本为 8 / `0.7.0-reading-card-trial`。仅版本号相同不算代码核对完成。

### 2. 构建与安装

下面是原机历史路径，必须先检查实际存在，再执行；不要照抄不存在的路径。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-pre-device.ps1 -JavaHome 'D:\android_stufio\android-studio\jbr' -SdkRoot 'D:\Android\Sdk' -ExpectedVersionCode 8 -ExpectedVersionName '0.7.0-reading-card-trial'
```

该入口依次执行 16 组桌面逻辑、Android 编译、JUnit、lint、APK 构建与版本/权限/签名/OCR 资源检查。任一失败先记录并修复，不继续安装失败包。记录源码 HEAD/工作区状态和 APK SHA-256，再确认手机已有安装的签名一致，使用 `adb -s 实际设备序列号 install -r app\build\outputs\apk\debug\app-debug.apk`。不默认加降级参数、不卸载清数据；原机若已有更高版本需先核实。

### 3. 无 API 的界面验收

在助手首页开启“本页合成测试”，启用无障碍，点取字浮窗；原文整理页顶部有“免 API 测试阅读卡（虚构短文 / 长文）”。仅此页有该按钮，真实聊天没有假译文入口。

依次测试三条消息、原文切换、上/下停靠、第三条长文内部滚动、展开/恢复、收起/浮窗恢复、重新取字。演示标题明确标为“本地演示 · 非真实翻译”。重复段落是有意构造的长文压力样本，不用于判断模型质量。

恢复后位置与内容一致；界面切换没有请求。测试大字体/横屏/分屏：空间不足时整张卡可滚动，所有按钮都应能找到。再试底层滚动、锁屏、返回桌面和设置页，不能发生过期定位、旧结果意外重新出现或设置页被取字。

首页底部另有“跨屏长节点样本”，开头和结尾明确标记。将结尾滚出屏幕，检查取到的原文是否仍包含结尾；记录原文长度和首尾核对结论。该结果只证明合成节点行为，真实 MSG 必须另测。

### 4. 真实消息与长文补取

用户自行打开指定偶像页面；助手只操作用户指定样本。先不启用快捷翻译，检查推荐选中的是否正文，不准为了减少操作把所有 BODY 全选。

长气泡直接读取全文时：核对确认区是否包含真实首尾，普通流程翻译即可。几何边界提示是风险提示，不是自动完整性证明。

取不全时：展开“长消息补取 / 草稿”，从开头只选同一条消息，勾选“同一条长消息”，点加入。点击收起继续取字，手动滚动留下几行重叠，再点“补取这一屏”。重新选择这条消息的后续内容并确认加入。已知单条节点可加入；多行 OCR 只在手动确认后按原次序合并；多个不同节点消息或混合来源拒绝。每次修改选择后同条确认会自动取消，必须重新核对。

成功补取后检查完整草稿，不能包含下一条头像/作者/时间或漏掉段落。只有在确认首尾完整后，勾选“改用草稿翻译”，点准备，再核对发送区确实为整个草稿，最后确认发送。补取期间草稿保存在内存；切应用/窗口、锁屏、服务重启会清除。源码现在会在准备、发送和译文回调前重新读取标题：可靠识别到另一位成员时清理旧草稿和阅读卡；标题缺失时不会把新内容并入旧草稿。真实 MSG 页面是否提供可读标题、同窗口切换能否被系统事件及时通知，仍须真机确认。

拼接要求至少 12 个 Unicode 字符（其中至少 8 个非空白）的唯一精确重叠。OCR 一个字识错、换行不同、重复句导致多个拼接位置时可能拒绝；这是保守退路，不自动模糊纠错。草稿最多 6000 个 UTF-16 字符、12 个成功收集片段；超限不截断发送，也不声称支持无限长消息。纯 OCR 无法恢复未识别的 Emoji。

### 5. 少量真实 API 与快捷模式

Key 只由用户在手机设置中输入，不能放在终端、聊天、Git 或测试截图。用一条短文、一条长文验证 DeepSeek 返回、符号、原文/中文对应；本轮没有自动语言质检，用户不懂日语时不要因模型自评就记语义通过。可由另一模型结合原文辅助检查，但仍记录不确定点。

确认默认手动流程正常后，由用户自行决定是否启用快捷翻译。该开关默认关闭，可随时关闭。保守推荐不覆盖所有真实节点结构，出现确认页是预期退路，不能放宽规则强行让所有页面自动付费。

## 交接给开发助手的执行要求

先读实际源码、Git 状态、设备/JDK/SDK，再执行以上步骤；优先免 API 演示与合成节点，之后由用户准备私人页面和 Key。可以自动执行构建、安装核验、合成页点击和日志检查；系统授权、私人页面选择、Key 输入及有费用测试范围由用户完成或明确授权。每个“通过”写版本、命令/动作、结果、证据位置；截图/XML含私人聊天时仅留本机，不提交仓库。发现矛盾先记录核实，不根据旧文档或模型判断宣称完成。不要自动升级依赖或把历史 handoff 草稿覆盖到 app。
