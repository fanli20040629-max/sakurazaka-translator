# 当前代码审核与改进方案

更新时间：2026-09-16。本文件记录当前源码事实与后续规划；用户最新指令优先。历史构建和截图证据继续有效，但不能代替本轮新代码的构建/真机验收。

## 给用户的简明说明

本轮主要把“读页面”“跑 OCR”“整理勾选内容”分开，让代码更容易维护，并修复了原有测试没覆盖到的排序和状态问题。现在勾选后会建立一份本地待翻译请求，但没有调用任何翻译 API。

界面改为“已选择待翻译片段：X 项（仅预览，未联网）”。一行 OCR 可能只是半条消息，也可能是作者、时间或按钮；目前必须由你手动选择。不能把“片段数”当成真正的聊天消息数。

## 当前证据与限制

- 生产服务使用唯一的 CaptureCoordinator，字段名为 captureCoordinator；旧 RequestGate 只在历史逻辑测试中使用。
- NodeTreeReader 负责节点树读取；OcrProcessor 负责 ML Kit 调用与结果转换；OcrSelection 统一候选和勾选状态。
- 请求链路已接入：OCR 候选 → 用户勾选 → ConfirmedMessageFactory → TranslationRequestFactory → 本地请求预览。
- 节点文本仍是分区展示，尚未提供与 OCR 相同的逐条确认界面；不能宣称所有节点正文都已接入翻译。
- OCR 仍对整个目标窗口识别，不是局部裁剪。OCR 全部标记为 MEDIA_CANDIDATE，作者/时间不自动分类。
- 代码不主动修改已提取原文、Emoji 或换行；这不保证 OCR 引擎本身没有漏字或误识别。
- 本轮七组桌面纯 Java 测试通过（JDK 17，UTF-8，-Xlint:all）。NodeTreeReader、OcrProcessor、Service 等 Android 依赖文件不在该测试编译范围。
- 本轮已在 Windows PowerShell 5.1 运行七组逻辑测试、完整 Android Java 编译、lint、assembleDebug 和 APK 静态检查；用户随后提供首轮目标页面视觉证据和一个 `283ms` 端到端样本。ADB 当前无设备，设备端版本身份、完整真机矩阵和稳定性能仍无充分证据。
- 本轮 APK 为 `0.3.1-probe-review` / 4，大小 `53,400,368` 字节，SHA-256 `463CE6B4EAD735B07EF442B5DE09B2BF551A614517F18FA7AA95D9DA22C6E249`；v2 签名有效，无网络权限，包含日文 OCR 模型。
- 当前工程已在 Git 仓库中；本轮验证脚本和状态记录为本地未提交改动，未推送 GitHub。

## 查验结果与已落实优化

| 维度 | 发现的问题 | 本轮处理 | 证据/剩余限制 |
| --- | --- | --- | --- |
| 正确性 | 实际 ID 为 n2:text / n10:text，旧“尾部数字”修复无效 | 节点先按数值 traversalIndex 稳定排序，再按 top/left 排序，不解析 ID | 回归测试先失败再通过 |
| 正确性 | OCR 返回顺序、勾选顺序、请求顺序可能不一致 | 显式坐标排序，坐标相同保留遍历/供应方输入顺序；共用同一候选状态 | 反向勾选、同坐标和请求顺序测试通过 |
| 稳定性 | 空白 OCR 片段进入构造器会抛异常 | 候选入口和转换入口排除空白，保留非空原文 | 空白候选回归通过 |
| 稳定性 | 协调器允许已完成任务再次进入 OCR、允许跳阶段 | 仅允许 NODES → SCREENSHOT → OCR；旧回调不释放新任务 | 生产协调器纯逻辑测试通过；真实回调需手机验证 |
| 数据正确性 | 校验器接受空白译文、重复请求 ID 可能误对应 | 拒绝空白译文、构造请求时拒绝重复 ID；保留 Provider 警告 | 回归测试通过；模型返回 ID 校验尚未实现 |

| 安全/隐私 | 文档曾过度描述“已过滤所有作者时间” | 界面和文档明确手动选择，未将片段误称为消息 | 未联网；用户勾选不是后续图片上传的隐含授权 |

## 性能后续规划

优先级遵循：准确性约等于美观性，高于 token 消耗，再高于响应速度。

1. **先测量，不先压缩图片。** 在同一手机上记录节点读取、截图复制、OCR、候选渲染的分段耗时，以及连续取字前后的内存。当前显示的 OCR 耗时从采集起算，是累计时间，不是独立的纯 OCR 时间。
2. **确认区域后局部 OCR。** 保留原始窗口坐标及裁剪偏移，测试局部坐标加偏移后的还原；对小字与符号先保证识别质量，再决定是否缩放。1080×2340 的 ARGB_8888 软件 Bitmap 约 9.6 MiB，不含硬件缓冲区、OCR 工作内存和 UI。
3. **减少重复窗口查询。** 一次事件中尽可能复用窗口快照；但展示结果前仍必须重新校验页面，不能用缓存造成旧结果上屏。先记录查询频率，不凭感觉给出加速百分比。
4. **谨慎迁移线程。** 当前节点遍历和 UI 构建在主线程，ML Kit 返回异步任务；单线程 executor 主要用于截图回调，不代表所有 OCR 运算由该线程执行。先确认耗时，再迁移节点处理，并携带同一页面身份。
5. 不添加持续后台识别、自动滚动或大量新缓存；这会改变耗电和隐私边界。

## 结构与 API 接入前门槛

| 顺序 | 具体工作 | 通过标准 |
| --- | --- | --- |
| 1 | 在原电脑完成七组逻辑测试、compileDebugJavaWithJavac、lintDebug、assembleDebug | 每一步退出码 0；记录 APK 版本和 SHA-256；最终权限检查通过 |
| 2 | 复测候选与生命周期 | 反向勾选顺序正确；取消全部后归零；关闭/切页/锁屏后旧请求和卡片不再可见；快速重复点击无重叠任务 |
| 3 | 消息边界和区域适配 | 用普通、长文、相同文本、语音、图片样本核对；同文不同位置保留；标题/作者/时间不自动加入；未知区域交给用户确认 |
| 4 | 完整消息模型 | 加入文字/图片/语音类型、完整边界、pageToken、来源及警告；只有有证据的消息才分组，不能按 OCR 行伪造气泡边界 |
| 5 | 翻译校验与可替换 Provider | 返回项包含消息 ID；空/多/少/重复/错序项可检测；符号保护可往返；明确换行规则；有超时、取消和有限重试 |
| 6 | 风格与云端能力 | 两位偶像使用各自的可编辑风格资料；Provider 的文本/图片能力分开声明，不能假定 DeepSeek 的任意接口都接受图片 |
| 7 | 相邻中文显示 | 同一 pageToken 下定位；滚动/切页失效；不遮挡关键按钮；字体/间距由真机视觉确认 |

同步 TranslationProvider 接口当前只是草案：未来网络请求不可在主线程调用；必须补取消和页面身份校验后才进入生产。

TranslationRequestFactory 只构造请求，不能从传入列表证明“用户一定确认过”。当前保证来自界面的勾选流程。后续网络发送层应只消费当前页面的显式操作，不能靠一个 public boolean 当权限门槛。

## 安全规划

- 当前源码 Manifest 显式移除 INTERNET 和 ACCESS_NETWORK_STATE，没有新增网络实现；本轮新 APK 权限检查确认两项权限均不存在。
- 当前订阅正文和截图只在内存中处理；关闭预览时释放应用持有的选择状态，不宣称能立刻从 JVM 堆或 OCR 库内部安全擦除全部数据。
- API Key 使用 Android Keystore 管理加密密钥，用其加密 API Key 后保存密文；Keystore 不是直接存任意字符串的保险箱。禁止进入源码、Git、日志或普通明文配置。
- 未来只允许 HTTPS；禁用或校验跨主机重定向，避免 Authorization 被发给其他服务；限制输入、响应和图片尺寸；聊天原文、博客和风格资料作为不可信数据处理。
- 局部图片上传需界面明确提示内容和服务商；当前手动勾选 OCR 文本不等于授权上传整屏。
- 接口失败区分超时、认证失败、配额、格式错误、取消和页面过期。用户提示易读，诊断日志不记录正文、密钥或完整响应。
- 不为提升识别率绕过目标应用的安全窗口限制。
