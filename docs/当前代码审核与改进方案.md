# 当前代码审核与改进方案

## 最新增量：0.5.0-translation-trial / 6

现已在下面 0.4 结构上实现保守分组建议、SymbolProtector、带消息 ID 的返回校验、DeepSeek 文本 HTTP、单请求取消/截止时限、Keystore 加密设置、两个风格档案及确认/中文卡片。Manifest 现在有 INTERNET 并禁用明文流量；不上传图片。当前风格手动选、Key 不回显，设置页从取字范围排除。具体模块/验收见 [试用计划](TRANSLATION_TRIAL_PLAN.md) 和 [当前交接](本轮优化验收与交接.md)。

复核发现同列表项中的 text 与 description 即使不同来源也可能被建议合并，新增回归先复现失败，现已要求来源一致。其他边界保持保守：位置重叠、冲突字段、辅助角色、截断不合并；缺少结构不猜。已有符号可校验保护，但复杂颜文字、OCR 已丢符号、日语含义/风格质量仍需真实样本，不能称“自动表情纠错完成”。

当前九组桌面测试及协议/HTTP 模拟测试见 [执行记录](优化执行记录.md)。本机未打包新版、未调用真实 DeepSeek、未验证 Keystore/窗口生命周期；必须先在 Windows 构建并执行 C01～C13。以下审计保留为上一阶段记录，其中“无网络/未接 API”不再描述 0.5。

更新时间：2026-09-17。用户最新指令优先；本文件记录源码事实和改进门槛，不是所有功能已通过真机验收的声明。操作入口见 [本轮优化验收与交接](本轮优化验收与交接.md)。

## 当前结论

当前版本 `0.4.0-probe-candidates` / 5 在原有探针上完善了“把可确认的原文安全地选出来”。节点与 OCR 共用 CandidateSelection，PageToken 贯穿采集和本地请求，CandidatePanel 承担展示。没有接入翻译和网络。

节点文本现在可以勾选，节点先显示、OCR 后到不重置选择。程序不改已有原文中的表情和换行，但不能恢复 OCR 引擎已漏掉的符号。所有片段默认不选，作者/时间仍需人工核对；当前不是自动只识别聊天正文。

七组桌面逻辑测试通过，新增候选测试 41 项。Java/XML 仅做语法检查；本机缺少 Android SDK，本版本的 Android 构建、lint、APK 和真机测试均待 Windows 执行。旧版本检查结果见 [真机记录](DEVICE_TESTS.md)，不能套用。

## 已落实的改进

| 维度 | 问题 | 实现 | 仍需确认 |
| --- | --- | --- | --- |
| 原文准确性 | 过去只有 OCR 可勾选，无法选节点中保留的正确表情 | 节点/OCR 共用选择；不替换、规范化或修剪非空原文 | 节点本身是否完整；OCR 的错误仍可能存在 |
| 数据边界 | 请求缺少页面身份、完整矩形和风险 | PageToken、四边界、SCREEN/IMAGE、来源 ID、风险传入请求 | 矩形是片段边界，尚不是整条气泡 |
| 页面正确性 | 旧选择或迟到 OCR 可能影响新状态 | 页面 token 校验；重复 OCR 拒绝；旧卡片操作不关闭新卡片 | Android 实际事件顺序需手机验证 |
| 状态一致性 | 成功/失败卡片两条路径重复；刷新可能影响选择 | 单个 CandidatePanel，先建节点后追加 OCR；失败更新同一卡片 | 真机勾选、滚动和失败用例 |
| 可读性 | Service 承担大量候选 UI 细节 | 抽出只展示的面板；Service 保留采集与资源所有权 | 当前不继续拆框架，先验证行为 |
| 保守分类 | 时间或控件误判可能丢失真实正文 | 辅助候选默认折叠但可显式补选，风险随请求保留 | 不能据此宣称自动正文过滤通过 |
| 坐标与顺序 | 节点和截图坐标直接混排会误导 | 各来源按位置排序，组间分开；混选提示重复风险 | 校准坐标与消息对应后才能合并 |
| 窗口事件 | 重叠矩形不足以证明事件属于浮窗 | 只按已登记的浮窗窗口 ID 确认归属 | 未知事件保守失效可能误关卡片，属于本轮首要设备门槛 |
| 资源 | OCR 与 UI 持有同一图片，过早回收会崩溃 | 先解绑视图，再释放预览租约；等 OCR 完成再释放物理租约 | 模型通过不代表真实 Bitmap/回调通过 |
| 构建交接 | 旧版本和旧 APK PASS 易被误当新代码结论 | 版本/Windows 检查脚本一致，当前与历史记录分开 | 新包必须重新构建并记录身份 |

前轮已实现的节点数值遍历排序、空白候选排除、重复 ID 拒绝、状态机阶段约束、测试移出 APK 及跨电脑构建配置继续保留。未升级工具链或依赖。

## 性能与结构后续规划

优先级：准确性约等于美观性，高于 token 消耗，再高于响应速度。

1. 在同一手机记录节点、截图、OCR 和候选渲染耗时，以及连续约 20 次取字的内存趋势。界面目前展示采集累计耗时，不能当成纯 OCR 耗时。
2. 节点最多 800 个、深度最多 80；节点读取和 UI 仍在主线程，复杂页面可能卡顿。先测量再决定分批渲染或迁移纯数据整理，避免未经验证跨线程持有 Android 节点。
3. 暂不新增大量缓存、后台自动识别或持续截图。1080×2340 的 ARGB_8888 软件图约 9.6 MiB，另有硬件缓冲和 OCR 开销；局部裁剪应建立在准确坐标之上。
4. 查询窗口的重复调用可在测量后适当合并，但结果上屏前必须重新确认页面。
5. 不为“架构美观”引入仓库层、事件总线或第二套选择模型。现有未接生产的 domain 工具和历史 core_modules 不能当成已完成功能；接入前核对职责，避免重复实现。

## 安全与接口边界

- 源码 Manifest 继续显式移除 INTERNET 和 ACCESS_NETWORK_STATE，本轮未增加网络实现；新 APK 权限仍需构建后核实。
- 当前正文与截图仅在内存处理。关闭清理应用引用，不声称立即从 JVM 或识别库中安全擦除所有数据。
- TranslationRequestFactory 只是构造数据；勾选不能代表消息边界已正确，也不等于未来网络层有权上传图片。
- 后续 API Key 以 Android Keystore 中的加密密钥保护，再保存密文；不把 API Key、正文或完整响应写入源码/日志。
- 分享 APK 可让每人配置自己的 Key；若统一提供共享额度，则使用后端保管公共凭据，不放进 APK。
- 后续只用 HTTPS，校验重定向目的地，限制图片/输入/响应大小；页面、Blog 和模型输出都是不可信内容。
- 图片上传展示明确的局部内容及服务商，遵循用户选择。OCR 无置信度或分数高都不能证明 Emoji 正确。
- 不绕过目标 App 的安全截图限制。
