# 成员识别与自动风格匹配实施计划

> 执行方式：按 writing-plans / test-driven-development 分步实施，并以独立代码复审和 verification-before-completion 收尾。用户已批准实现，不再等待重复确认。

> 2026-09-22 实现状态：源码实现和 JVM 逻辑回归已完成；Android 完整构建、真实标题读取和真机验收仍待另一台 Windows 电脑核对。当前新增的长文追加策略还会在身份未确认时阻止把新内容并入旧草稿。

**目标：** 从有结构依据的聊天标题识别当前成员，自动匹配本地风格；换人后隔离草稿/旧译文，不用正文提及的人名猜作者。

**架构：** Android 无关的 MemberResolver 负责标题证据及姓名匹配，MemberSession 负责身份连续性和草稿归属。设置层保存可扩展的档案与姓名别名；采集服务在取字、发送和结果回调前核对身份，界面展示自动结果并提供本次采集的手动确认。保留现有 PageToken 与取消机制。

**技术：** Java 17 / Android 原生 View / minSdk 34 / SDK 36，无新增依赖。

## 全局约束

- 保留现有未提交阅读卡实现、签名、Key、SDK 配置，不重置、不覆盖整个工程、不自动上传 GitHub。
- 优先节点标题，不识别头像，不扫描正文子串，不新增云端图片识别。OCR 姓名辅助留到节点实测后，不作为本轮自动匹配依据。
- 只有唯一可靠标题和唯一档案匹配可自动采用；缺失、冲突或未知成员不沿用上次风格，不自动发送。
- 标题暂时缺失不等于换人，暂停自动操作；可靠身份改变才自动清除旧草稿/译文，并使旧请求显示失效。
- 手动确认不保存为全局猜测，也不能开启快捷发送。换页/重新取字后必须重新确认；若同一个未知标题原样恢复，重新确认后可以继续同一草稿；标题缺失没有跨页身份锚点，不能续接旧草稿。
- 无论自动还是手动，长文草稿绑定成员身份；不同成员不得合并。已上传请求无法撤回或保证不收费。
- 自动识别只做本地处理，不自行采集/发送，页面事件不触发翻译 API。
- 默认两份旧档案保留，允许添加至 20 份；旧姓名默认作为精确匹配名。别名每行一个，不做昵称/简繁猜测；重名冲突不得自动选第一个。
- 当前仍是未交付版本 8 / 0.7.0-reading-card-trial，本功能用源码文件和最终提交核对，不能只看版本号。
