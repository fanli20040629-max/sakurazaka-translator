## 1. 要交付的体验与目标

用户停留在目标消息页，主动点击“取字”。助手先展示从节点读取的文字，再提供图片 OCR 候选。用户能看清正文、保留原有符号与换行、核对来源、处理不确定片段，并随时关闭卡片。图片文字由用户选择是否纳入；出现失败时仍能查看已经取得的有效节点结果。

本轮交付是一个**可复测的正文整理版探针 APK**。长期目标仍是日文到自然简体中文的翻译助手，但本轮以取字质量和任务可靠性为验收对象。

| 目标 | 可检查的结果 |
| --- | --- |
| 原文保真 | 保存的节点 text/desc 与输入逐字一致，含空白、组合 Emoji、颜文字、花、爱心和换行 |
| 不丢内容 | 不误删独立位置的重复句；预算、部分可见和读取异常均有提示 |
| 来源清楚 | 节点和 OCR 原文可分别核对；没有自动猜字、自动覆盖或未经选择的图片文字混入 |
| 页面可信 | 关闭、切页、锁屏后旧结果不重现；不确定页面变化时明确过期并禁用修改正文的操作 |
| 任务可恢复 | 连点受控；已知终止路径都释放任务占用；在途资源不提前释放 |
| 容易复测 | 卡片有版本、固定关闭入口和可滚动正文；测试结果、APK 和未验证项可追溯 |

“原文逐字一致”指对已获得节点字段的保存，不代表目标 App 提供了完整正文。“卡片能显示”“截图成功”“OCR 有字”“正文验收通过”分别记录。

## 3. 官方资料核对后的关键修订

查询日期为 2026-09-13。下面区分平台事实与本项目设计；在线资料可能包含 API 37 等内容，不能直接用于 compileSdk 36。

| 核对事实与来源 | 对方案的影响 |
| --- | --- |
| 指定窗口截图自 API 34 提供，可避免无障碍 overlay 覆盖截图；有安全窗口、无效窗口、频率等失败状态。[AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService) | 继续使用 takeScreenshotOfWindow；保留原始错误码，不换成全屏采集，不自动重试 |
| Task 的取消不会触发失败监听，完成监听涵盖成功、失败、取消。[Task](https://developers.google.com/android/reference/com/google/android/gms/tasks/Task) | 首选一个非 Activity 绑定的 addOnCompleteListener；显式分类结果，另处理 process() 同步异常 |
| AccessibilityNodeInfo.recycle() 自 API 33 起无实际作用；屏幕边界受系统放大影响，API 34 的窗口边界不随放大缩放。[AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo) | 修订旧“逐个 recycle 防泄漏”要求为不长期持有节点引用；同时保存窗口/屏幕边界，不能猜坐标比例 |
| 窗口事件有窗口 ID、内容变化与窗口变化类型，可区分处理。[AccessibilityEvent](https://developer.android.com/reference/android/view/accessibility/AccessibilityEvent) | 元信息足够时精确失效；事件不读取目标正文；未知来源不全局忽略 |
| 日文 bundled 依赖仍列为 16.0.1；输入图像质量影响识别。[ML Kit Android](https://developers.google.com/ml-kit/vision/text-recognition/v2/android) | 保持本地原尺寸输入；本轮不新增云 OCR、中文模型或盲目放大 |
| OCR 行可提供文字、边界、角点与置信度。[Text.Line](https://developers.google.com/android/reference/com/google/mlkit/vision/text/Text.Line) | 保存原文与定位；置信度仅诊断，不当准确率、不据此删字 |
| wrapHardwareBuffer 的 Bitmap 保有底层引用，允许调用方关闭原 HardwareBuffer。[Bitmap](https://developer.android.com/reference/android/graphics/Bitmap) | 明确包装图、软件副本、原 Buffer 的不同所有者，避免重复释放 |

本地 SDK 36 的 javap 检查确认：View.createAccessibilityNodeInfo() 与 AccessibilityNodeInfo.getWindowId()/getBoundsInWindow() 可用；View.getAccessibilityWindowId() 不在公开 SDK 中。View.getWindowId() 返回的 WindowId 对象也不能当无障碍整数窗口 ID 使用。

因此，拟在本应用卡片 attach 后通过自己的节点取得窗口 ID，再与窗口列表核对；这是待真机验证的实现方案，不是已验证行为。拿不到可靠身份时使用保守过期策略，不访问隐藏 API。

本地缓存的 Tasks 18.2.0 确认存在完成监听及 isCanceled()/isSuccessful()；OCR 行确认存在 getText()/getConfidence()。边界/角点等使用前仍由锁定 classpath 编译确认。缓存中存在某版本不替代最终依赖解析报告。

## 5. 模块、数据契约与实现原则

### 5.1 最小模块

| 模块 | 输入与输出 | 职责边界 |
| --- | --- | --- |
| TargetWindowResolver / 服务适配 | 窗口元信息 → 已确认目标与布局 | 包名、活动应用窗口、displayId、配置代次；不在事件中遍历正文 |
| NodeSnapshotCollector | 本次目标 → 不可变 NodeRecord 列表与限制 | 工作线程按本次请求读取；Android 节点不传给后续算法或 UI |
| ProbeModels | 页面、片段、阶段结果 | 纯 Java 数据契约；可合并小类 |
| TextAssembly | 节点/OCR 记录 → 有来源的片段 | 分类、稳定排序、严格去重、选择投影；无 Android/ML Kit 依赖 |
| CaptureCoordinator | 用户动作、事件、适配回调 → 快照/显示指令 | 唯一任务状态、页面有效性、终止和资源交接；复用 RequestGate/ResourceLease 的合理部分 |
| Screenshot/OCR 适配器 | 已确认窗口/软件图 → 数据或错误 | 框架调用和资源边界；不直接修改共享 View |
| ProbeResultView | 当前快照 → 同一窗口内的展示 | 切入口、滚动、选择、拖动、关闭；不自行截图或 OCR |

不要求每行都拆成独立文件；职责必须能测试，不能造一套只供测试的平行业务逻辑。

### 5.2 数据字段

- PageToken：requestId、pageEpoch、configEpoch、包名、windowId、displayId、窗口边界、方向、可用区域/密度相关布局信息。ID 只在本进程、本次请求内有效。
- NodeRecord：记录 ID、parentId、childIndex、遍历序号；原始 text 和 desc 分存；屏幕/窗口边界、可见标志、类名、可选资源 ID、集合项元信息；结构节点允许没有文字。
- OcrLine：记录 ID、blockId、原始块/行索引、rawText、图像像素边界、可选角点与置信度；无边界不等于无文本。
- TextFragment：来源 ID 列表、source、rawText/独立 displayText、role、可空 messageId、原始/展示位置、decisionReason、warnings、选择状态。
- ProbeSnapshot：PageToken、节点和 OCR 各自状态/错误、片段、限制、采集起止/展示时间、布局与对应关系是否已确认。只能容纳当前请求。
- Selection：以 fragmentId 管理显式选择；同一 OCR 候选不能重复追加；替换操作记录明确目标并可撤销。本次页面失效后禁止修改。

rawText 不 trim、不标准化、不删变体选择符；空值/空白判断不能改写原文。来源必须能回查输入字段；文本哈希不能当消息 ID。没有结构证据时不编造消息容器和条数。

1. 建立数据契约、协调器接口和可注入的时钟、节点、截图、OCR、资源、显示端口。

4. 完成/下一阶段派发前再次核对请求与窗口元信息；节点与截图并非原子操作，事件延迟仍可能造成不一致，诊断保留采集区间，不能宣称绝对同帧。
5. 深度上限继续 80，节点访问上限继续 800；增加文本预算，拟定初始总量 64 Ki UTF-16 单元作为可调工程限额，不作为性能保证。以完整字段为单位收录；单字段超预算保存明确的省略/超限记录，不截断半个 Emoji，也不把未保存字段标为完整。
6. 不可见父节点仍可作为结构继续检查子节点；纯屏外文字不进入默认正文。部分可见节点保留完整已返回字段并标风险，不能推算被遮住的是哪些字符，也不自动纳入“已确认可见正文”；用户核对后才能选择。
7. rawText、text/desc 冲突、父子关系、集合信息、边界分别保存。临时节点引用只在采集栈/工作任务内使用，结束即释放引用；API 34+ 不以 recycle 次数验收。
8. 节点为空或局部异常与窗口身份失败分开：身份仍可靠时继续一次截图/OCR；身份无法证明则停止，不借旧包名或旧 root 截图。

阶段出口：T01、T02、T09～T15、T18、T20、T23、T24 中与本阶段相关的生产用例通过；剩余 Android 适配实机项明确列出。能够用同一协调器驱动真实节点和截图路径。

### M2：正文分类、阅读顺序与去重

1. role 固定为 BODY、METADATA、CONTROL、MEDIA_CANDIDATE、UNKNOWN。只有具有明确结构/语义证据的节点才自动分类；“可点击”“像时间”“名字相同”均不足以删正文。
2. 先实现自造容器的确定规则，再接入有实际证据的目标规则；没有目标结构样本时使用 UNKNOWN 和手动选择，不硬编码猜测的资源 ID。
3. 同节点 text/desc 完全相同可合并展示，来源保留两个；冲突则两份可见。父子精确重复只有在归属唯一、结构确证时压缩；多个相同子句不能全部压成一条。
4. 部分包含、相似文字、坐标重叠都不能单独触发删除；不同消息或同消息不同位置的重复均保留。
5. 单列横排：组间按实际正文起始位置上到下；组内先确定性聚成行，再从左到右；原始索引打破平局。候选同行容差可从局部行高中位数推导，必须集中配置并用合成反例验证，不能用不满足传递性的近似 comparator。
6. 边界缺失、竖排/多列、关系不明：保留原始顺序或明确的局部顺序，标“顺序未确认”，不跨片段拼句。
7. UNKNOWN 默认可见但不自动纳入确认正文；提供“选为正文”和“排除”操作。它不能隐藏在诊断入口，也不能计入“自动正文通过”。

阶段出口：T01～T06、T09、T24 通过；规则能给出 decisionReason 和来源，目标规则不足时使用可见回退。

### M3：截图/OCR 候选与来源对照

1. 每次有效主动点击：一次节点采集、最多一次窗口截图、最多一次 OCR；在派发之前已关闭/失效则不继续启动下一阶段。
2. 节点结果完成即建立/更新正文卡片；截图到达后补充预览；OCR 完成更新独立候选列表，不重建窗口、不替换节点、不改变用户已选片段。
3. 截图工作线程取得 HardwareBuffer 后在 finally 关闭；包装图复制为软件图后不再保留。软件图由明确所有者交接，复制失败、过期、销毁都走清理出口。
4. OCR 适配使用单一完成监听，按取消 → 成功 → 失败分类。process() 同步抛错单独终止；结果解码/格式化异常也能清理。正常关闭卡片仅逻辑取消，不声称 ML Kit 底层已被取消。
5. 若 process 已返回在途 Task，不能因后续监听注册/适配异常就假定底层停止并回收 Bitmap；保留到可证明完成的清理路径，记录此适配故障。避免使用会随 Activity.onStop 移除的监听。
6. 坐标首版采用独立候选对照。保存窗口位置、图像尺寸、方向、屏幕/窗口坐标类别及放大状态能否确认；仅仅乘宽高比例不足以验证映射。
7. 坐标或消息对应关系未证实，一律标 COORDINATE_MAPPING_UNVERIFIED，自动融合关闭。可验证映射仅用于辅助定位，不成为自动覆盖授权。
8. 所有 OCR 行保留原始块/行顺序和边界；整理顺序单独保存。置信度不决定内容去留。OCR 没字、失败和节点没字分别展示。
9. 候选纳入采用按 ID 的集合更新；替换必须先指定节点目标并保留原文对照，可撤销。多重匹配不自动选“最像”的一条。

阶段出口：T06～T10、T14、T15、T19、T21 相关桌面用例通过。真实 GMS Task 适配检查尚未运行时独立标注，不用纯 Java 测试替代。

### M4：卡片、页面事件与生命周期回归

1. 默认正文页，另有图片识别、原文对照、诊断入口；都在同一 overlay 窗口中切换。
2. 头部显示实际版本、当前状态和固定关闭按钮。正文使用约 17sp、舒适行距和 12～16dp 内边距作为初稿；适配字体放大，不能仅靠颜色表达风险。
3. 截图默认折叠。保留当前请求的图像所有者引用以允许展开；关闭整个卡片先解绑 View，再释放所有者引用。若提前释放图片，必须禁用再次展开并明确提示，不能暗中重新截图。
4. 卡片宽度不超过可用区域，初始最大宽约 420dp；高度按实际可用区域受限，正文滚动。拖动按测量后的整卡尺寸约束，至少保证整个标题/关闭区可达，不仅留下任意 48dp。
5. 点击、拖动、切入口、折叠预览不启动新请求；OCR 候选到达保留当前页、选集、可见内容锚点和滚动位置。
6. 事件分类按第 7 节实施；合成页与 overlay 同包仍分窗口。配置更改、测试页离开/关闭开关同步失效，不能等下一次偶然页面事件。
7. 合成模式保留显式开关并绑定选定 Activity 的可见生命周期；不扩展到本应用所有页面。若引入新测试 Activity，必须同步收紧许可。
8. 窗口添加失败终止显示资格，继续安全清理在途资源；再次主动取字可恢复。服务中断/销毁/锁屏清除敏感界面与文本引用。

阶段出口：T11～T25 桌面可验证部分通过；卡片操作和 One UI 事件表现待真机检查。默认正文不能堆砌包名、坐标和调试字段。

2. 运行逻辑脚本、lintDebug、assembleDebug；每个命令检查退出码，失败修复后重跑受影响部分。

## 7. 协调器和页面失效规则

### 7.1 三个独立维度

不能用一个 busy 或 Showing 枚举同时代表运行、页面和窗口：

| 维度 | 建议状态 | 关键规则 |
| --- | --- | --- |
| 物理任务 | IDLE → NODES → SCREENSHOT → OCR → IDLE | 跳过未启动阶段；所有已启动阶段真实结束后才能释放占用 |
| 页面结果 | CURRENT / STALE / INVALID | STALE 禁止新结果写入和选集变更；INVALID 清除敏感显示 |
| 界面 | CLOSED / OPEN | 用户关闭后本请求永久不得 reopen；后台完成不改变 CLOSED |

软件 Bitmap 的释放需同时满足：OCR/转换等使用者已终止、ImageView 已解绑、当前卡片的预览所有者已放弃引用。折叠预览不等于永久释放预览所有权。

如果底层一直没有回调，展示“任务尚未结束，请稍后”；可提供关闭界面，但不以倒计时、盲目 sleep 或清空 busy 伪造物理结束。协调器只在完成快照处理/资源交接后开放新请求；重复终止回调幂等，旧请求不能操作新请求资源。

### 7.2 事件决策表

| 事件/动作 | 处理 |
| --- | --- |
| 已登记 overlay 窗口的内部滚动、切入口、布局刷新 | 忽略为目标变化；必要的前台/锁屏检查仍执行 |
| overlay 创建/移除产生的窗口集合事件 | 结合已登记 ID、窗口类型、当前目标身份核对；身份仍不明时保守标过期 |
| 目标文字/描述/子树变化、TYPE_VIEW_TEXT_CHANGED | 立即拒绝本请求后续结果；已有显示标 STALE 并禁用纳入/替换 |
| 目标滚动、确定同包切页、窗口被替换/移除 | INVALID，关闭旧卡片；不自动重新采集 |
| 离开目标、锁屏、中断、销毁、关闭测试开关、修改目标配置 | INVALID，清除敏感内容；在途资源等实际终止后释放 |
| 方向、窗口尺寸、显示环境改变或不支持布局 | INVALID；重新核对布局后只接受新主动点击 |
| source 为空或 windowId 不明确的相关事件 | 不能当卡片事件放行；标 STALE，必要时因无法确认前台而清除 |
| 可证明无关的事件 | 忽略；仅记录匿名原因和计数 |

事件 XML 补齐实际使用的 typeViewTextChanged，继续按窗口/内容变化类型处理，避免 typeAllMask。自有 overlay ID 拿不到时不使用“同包＋矩形相交”作唯一证据；也不读取目标文字指纹来后台验证。

窗口根为空时，事件包名只能作线索，不能单独授权截图。仅在本次主动请求中已验证身份且后续同一活动窗口无失效证据时，才讨论根暂不可读的 OCR 回退；无法满足这一条件就显式停止。

## 8. 界面组织与失败提示

默认信息层级：

~~~text
正文整理 · 实际版本                         关闭
当前状态 / 待确认数量 / 部分可见提示
正文   图片识别   原文对照   诊断

已确认正文
  原文保留换行、符号和段落
待确认片段（数量）
  可查看来源，可选为正文或排除

截图预览：展开 / 折叠
~~~

页签可采用可滚动按钮行或两行布局，保证窄屏/大字体可用；不为四个入口强行压缩字号。错误提示用用户能采取的动作表达，技术码放诊断：

| 情况 | 用户可见说明 | 恢复 |
| --- | --- | --- |
| 截图被保护 | “此窗口无法截图；可查看已读取的文字” | 保留有效节点，不绕过保护 |
| 节点为空、OCR 有结果 | “未取得节点正文，以下为图片识别候选” | 用户核对选择 |
| OCR 失败/取消 | “图片识别未完成，节点文字仍可查看” | 底层结束后可再次主动取字 |
| 页面内容变化 | “页面可能已变化，请重新取字” | 旧选集只读；新请求重新开始 |
| 正文预算/遍历预算触顶 | “本次读取达到上限，内容可能不全” | 分屏取样；不暗中截断并宣称完整 |
| 窗口身份或布局不支持 | “当前页面无法确认／请返回支持的竖屏页面” | 不执行不可靠截图 |
| 物理任务未结束 | “仍在处理上一次取字” | 不排队、不自动重试 |

## 9. 测试设计与验收门槛

### 9.1 测试分层

- **桌面生产逻辑**：纯 Java 测试调用 TextAssembly、CaptureCoordinator、资源/结果桥接逻辑；受控端口模拟回调顺序、节点异常、关闭与失效；不需要模拟器。
- **Android 适配**：锁定 SDK 编译；手机测试真实窗口、Bitmap 和 GMS Task 监听。可在显式 debug 合成页使用真实 TaskCompletionSource/CancellationTokenSource 受控触发实际 OCR 适配终止代码；不能另写一套“测试版完成逻辑”。注入入口仅 debug、显式启动、使用自造数据，不导出可任意触发采集的组件。
- **真机内容质量**：先合成，再目标 App；人工确认遗漏、符号、重复、顺序、图片混入。真机适配与目标正文是两个不同证据层。

脚本扩展为编译和执行全部新增纯 Java 入口，使用 --release 17、UTF-8，并逐组输出断言数量。若某个适配测试依赖 Android，仅编译或假端口通过不写为真实 Task/Bitmap 已通过。

### 9.3 手机顺序与内容门槛

1. 合成页：text-only、desc-only、冲突字段、父子聚合、两个独立重复句、真正跨多屏长文、部分可见、图片符号、导航/媒体混排、异步内容更新。
2. Android 行为：断网 OCR、关卡片、连点、目标滚动、切页、锁屏、服务停启、字体放大和布局变化；确认图片不落盘、旧窗口不重现。
3. 目标 App：短消息、多条同屏含重复、长文/边缘截断、图文混排。找不到样本写未验证；图文混排不自动算“图片内文字”通过。
4. 每次只比较当前屏幕。记录原始节点字段保存差异、可见正文遗漏、误去重、顺序、未经选择的媒体混入、OCR 字级问题和风险提示；不用总体准确率掩盖整条遗漏。
5. P0.5 门槛：合成矩阵通过；至少一条正文来源在四类目标页面达到原标准，无未提示整块遗漏、误去重或错误串页。少量 OCR 字级问题如实列出。手动选择回退不算自动正文质量通过。

发布“待复测 APK”可接受 Android/目标未测项明确存在；发布“P0.5 通过”不能缺上述证据。本轮不要求用 20 页/30 次扩展验收替代最初四类门槛；扩展稳定性属于后续工作，可在首次闭环后安排。

## 10. 构建、检查点与交付

### 10.1 顺序命令

以下用于代码实施后的验证，本次规划没有执行构建。保留现有缓存和签名。每条失败即停止其依赖步骤。

~~~powershell
$env:JAVA_HOME='D:\android_stufio\android-studio\jbr'
$env:GRADLE_USER_HOME='D:\Projects\sakurazaka-translator\.gradle-home'
$env:Path="$env:JAVA_HOME\bin;$env:Path"

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-probe-logic.ps1
if ($LASTEXITCODE -ne 0) { throw 'Logic tests failed' }

.\gradlew.bat :app:lintDebug :app:assembleDebug --offline --console=plain --no-daemon
if ($LASTEXITCODE -ne 0) { throw 'Lint/build failed' }

$probeApk='D:\Projects\sakurazaka-translator\app\build\outputs\apk\debug\app-debug.apk'
& 'D:\Android\Sdk\build-tools\36.0.0\aapt.exe' dump badging $probeApk
if ($LASTEXITCODE -ne 0) { throw 'Badging failed' }
& 'D:\Android\Sdk\build-tools\36.0.0\aapt.exe' dump permissions $probeApk
if ($LASTEXITCODE -ne 0) { throw 'Permission inspection failed' }
& 'D:\Android\Sdk\build-tools\36.0.0\apksigner.bat' verify --verbose $probeApk
if ($LASTEXITCODE -ne 0) { throw 'Signature verification failed' }

$probeEntries = & "$env:JAVA_HOME\bin\jar.exe" tf $probeApk
if ($LASTEXITCODE -ne 0) { throw 'APK listing failed' }
$probeEntries | Select-String 'Jpan_ctc|libmlkit_google_ocr_pipeline'
(Get-Item -LiteralPath $probeApk).Length
Get-FileHash -LiteralPath $probeApk -Algorithm SHA256
~~~

退出码只是第一层：检查实际版本/包名、签名与旧包兼容、权限确无两项网络权限、模型及 native pipeline 都存在。lint 保留真实提示，不新增大范围 suppression。必要时查看 compile/runtime 依赖报告，不能只凭缓存目录推定实际解析版本。

缺缓存时按具体错误补官方依赖，不清缓存、不关闭 TLS。Git 提交明确列相关路径，禁止 add --all 带入截图；只建本地恢复点。平台强制权限审批仍按实际要求执行。

## 11. 风险、回退与停止条件

| 风险 | 当前决定 | 对交付的影响 |
| --- | --- | --- |
| 目标节点结构不足 | UNKNOWN 可见＋手动选取，自造结构测试先行 | 可交付探针；不能声称目标自动分组已验证 |
| 坐标/跨来源匹配不足 | 独立候选对照，自动融合关闭 | 可交付；诊断注明未验证 |
| 页面事件无法精确区分 | 保守过期，禁用旧选集操作；无法确认前台则清除 | 若频繁误失效影响使用，继续修复，不能称体验通过 |
| 根为空且身份不明 | 拒绝采集，不使用历史包名授权 | 明确节点/OCR 前置条件受限 |
| 安全截图失败 | 保留合法节点路径，不绕过 | 两条路径都不可用时停止自动取字路线，另议手动入口 |
| 在途任务不回调 | 关闭 UI 但保留物理占用与必要资源 | 单列故障；不能用超时解锁保证“永不卡住” |
| OCR 符号仍错 | 节点保真，图片候选对照，人工核对 | 不保证图片符号 100% 识别 |
| 无设备/缺目标样本 | 完成桌面部分，逐项标待测 | 不阻断 APK 交付，但阻断 P0.5 验收 |
| 新增实现依赖未缓存 | 先用已锁定依赖和现有自测机制 | 只为必要缺口补依赖，不升级整套工程 |

## 12. 工作量与下一次启动
