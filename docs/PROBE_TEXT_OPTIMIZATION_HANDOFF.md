## 3. 总体实现约定

保持 Java 17 源码兼容、原生 View、单模块、ML Kit 日文 `16.0.1`、现有 Wrapper/缓存/SDK/签名。不要因阅读最新文档顺手升级工具链。现有锁定版本下先确认 API 可用。

最小职责划分（允许合并小数据类，禁止另造只用于测试的一套业务逻辑）：

| 模块 | 职责 |
| --- | --- |
| `NodeSnapshotCollector` | 主动点击时读取 Android 节点，保存结构和限制信息，释放节点引用 |
| `TextAssembly` | 纯 Java 数据分类、排序、保守去重、来源选择；不依赖 Android 或 ML Kit 类型 |
| `CaptureCoordinator` | 生产请求身份、异步终止、结果有效性、资源所有权；通过接口接受截图/OCR/界面适配器 |
| `ProbeResultView` | 正文、图片识别、原文对照、诊断；在同一窗口内更新内容 |
| `TranslatorAccessibilityService` | Android 服务、窗口/锁屏/事件适配；不继续堆积所有正文算法 |

`RequestGate`、`ResourceLease` 能复用就复用，但只允许一个物理任务占用的权威状态。协调器抽取和基础测试与 M1 同步完成，不能到最后才补安全约束。采用主线程归并状态更新；工作线程只做受控复制/计算，回调携带请求 ID 返回主线程。Bitmap/HardwareBuffer 释放由明确的所有权接口承接，不能依赖界面是否还存在。

统一模型可集中在 `ProbeModels.java`：

- `PageToken`：requestId、pageEpoch、包名、windowId、显示区域/方向/窗口范围。
- `NodeRecord`：本次 ID、parentId、childIndex、遍历顺序、原始 text/desc、屏幕边界、可见状态、控件类型、可选资源 ID/集合项信息。结构节点即使无正文也可保存。
- `OcrLine`：本次 ID、原始 blockId/index、原文、像素边界/角点（如可用）；保留原始顺序。置信度仅作可选诊断，不当作准确率，不凭阈值删字。
- `TextFragment`：原始来源 ID 列表、source、rawText、可选 displayText、role、messageId、边界、decisionReason、warnings、用户选择状态。
- `ProbeSnapshot`：PageToken、节点记录、OCR 状态/行、片段、限制与错误、阶段时间戳；只在内存持有。

ID 仅保证一次请求内稳定，例如请求 ID＋来源＋本次索引。不要宣称它是跨滚动、跨会话的真实消息 ID，不以文字哈希去重。所有输出片段必须可回溯到输入记录和处理原因。

## 5. M1：结构化节点与原文保真

1. 主动点击后先验证目标窗口身份，提取节点结构和独立 text/desc 字段，再格式化显示。节点为空或 root 暂不可读时，若目标身份已可靠确认且截图可用，仍可执行 OCR；不能因无正文直接退出所有路径。目标身份无法验证时停止，不截图其他窗口。
2. 同一节点 text/desc 完全相同可合并展示并保留两个来源；不同则保留双方。明确正文角色后选用对应字段；无法确定显示来源冲突，不能固定优先 text 或固定优先 desc。
3. rawText 原样保存。不对原文做 `trim()`、全半角替换、标点/Emoji 过滤或全局正则清洗。空值检查不应改写有效内容。显示整理必须产生独立 displayText。
4. 保留 Unicode 组合序列、变体选择符、连接符和换行。若需长度截断，避免截断代理对/组合符号，保留明确截断标记；优先以完整片段为单位限制结果。
5. 节点回收使用 finally，禁止将 Android 节点对象留给异步正文处理。重复父子路径、读取异常、提前达到限制均须释放已取得的节点。
6. 复用原有深度/数量预算，并增加有理由的文本预算及测试。原始边界与可见交集分开保存。仅部分可见时标记 `PARTIALLY_VISIBLE`；这是风险提示，不等同于已证明少字。节点返回整段文本时，不能凭矩形推算哪些字符可见，更不能把屏外文字宣称为当前可见正文。
7. 显式合成测试只允许选定测试页面。新增独立测试 Activity 时，必须同步收紧准入；不要扩大到本应用所有页面。

验收：自造含小花、爱心、颜文字、组合 Emoji、多段换行的节点样本，rawText 逐字一致；同一节点两种字段冲突不丢失；无节点仍可走已授权目标窗口 OCR；节点异常不使任务永久 busy。

## 6. M2：消息分类、排序和保守去重

### 6.1 分类与分组

- role 取值：`BODY`、`METADATA`、`CONTROL`、`MEDIA_CANDIDATE`、`UNKNOWN`。messageId 可以未知，不能为了满足接口凭空分组。
- 分组优先使用可靠集合项/消息容器；其次使用设备证据确认且具有回退的目标规则；否则保留独立片段。
- 资源 ID 已有 `flagReportViewIds` 配置，但目标是否提供 ID 未知。不能猜测 ID、硬编码截图坐标或以成员名字作为规则。
- 时间格式只作弱证据，必须结合容器/控件语义。正文包含时间、姓名、导航同名词时不得被当控件删除；可点击也不等于非正文。
- 容器描述覆盖正文时不能重复整体加子节点；只在文本精确对应且父子归属已证实的情况下压缩展示，保留 provenance。部分包含但有新增文字/符号则不删除。
- UNKNOWN 必须可见、可选择，并显示数量；不能藏到诊断里造成“正文完整”的假象。自动识别失败时允许用户选正文/排除辅助片段，选择只作用于本次快照。

### 6.2 排序与去重

- 当前重点是单列横排消息：组按上到下排序；组内同一水平行按左到右，其他行按上到下；最后以原始索引稳定打破平局。
- 若需同行容差，先确定性聚类成行再排序，不写可能违反传递性的“近似相等”比较器。阈值集中命名并用样本验证，不能散落魔数。
- 大容器用子正文位置组织，不把覆盖整屏的父边界当单行位置。
- 两个独立消息的相同句子、同一消息中两个独立位置的相同句子都保留。
- 仅同节点重复字段或已证实的父子重复可压缩。坐标重叠、字符串包含、相似度都不能单独触发删除。
- 多列、竖排或消息归属不明时保持可追溯的片段，标注布局未确认。不要跨消息自动拼句；节点原始换行保留，OCR 行整理版和原始版并存。

验收：导航不会插入正文；语音时长不归属下一条消息；不同消息重复句不消失；父子去重保留独有符号；UNKNOWN 不被隐藏；相同输入输出顺序稳定。

## 7. M3：OCR 候选与来源对照

本轮探针默认一次主动点击执行节点采集＋一次目标窗口截图＋最多一次 OCR。节点结果先可读，OCR 完成后更新独立候选区，不重建卡片、不覆盖节点原文、不重置当前滚动位置。以后是否按需启动 OCR 等正文路径验收后另行决定。

| 情况 | 确定行为 |
| --- | --- |
| 已确定节点正文 | 正文默认采用节点原文 |
| 节点与 OCR 冲突 | 保留两份及来源，节点不被 OCR 自动改写 |
| OCR 独有内容 | 单独列为候选，用户决定是否纳入 |
| 对应关系不明/多重匹配 | 标记未确认，不自动融合 |
| 截图失败或 OCR 失败 | 节点照常展示，独立错误码 |
| 节点为空但 OCR 有字 | 显示 OCR 候选供选择，不伪称节点正文通过 |

- 跨来源匹配前必须核对 PageToken 和采集期间页面有效性；不允许取旧截图补新节点。
- 节点屏幕坐标与截图像素坐标使用显式转换模型。保存窗口位置、截图尺寸、方向和裁剪偏移；不能固定假定两者原点相同，也不能仅靠尺寸比例猜转换。全屏、非零窗口偏移、尺寸变化分别测试。
- 本轮可在坐标关系未验证时直接使用独立候选对照，记录 `COORDINATE_MAPPING_UNVERIFIED`。此回退允许交付，但自动融合必须保持关闭且不得宣称已验证。
- 大节点覆盖图片不代表图片文字已被读取；坐标重叠不得直接丢弃 OCR 候选。首版只做有结构/精确文字证据的对应，不做字符级自动纠错或模糊融合。
- 用户纳入 OCR 候选时保持 source 和 warnings；若替换某条节点片段，显式选择替换目标，保留原始对照；不能把选择默认变成重复追加。
- 图片内容未经用户选择不进入正文选集。识别错误不由语言模型猜补。
- 暂不添加图片放大、二值化、中文 OCR、云端识别或循环重试。若未来评估裁剪，应记录转换、原图/裁剪对照和独立请求所有权。
- 记录 `nodeStart/nodeEnd`、`screenshotStart/screenshotEnd`、`ocrStart/ocrEnd`、`resultShown`。使用单调时钟；分段耗时和整体耗时分开，异步重叠时不简单相加，不把“整体 597ms”当纯 OCR 耗时。

验收：节点符号不被覆盖；OCR 独有候选可选择；失败仍可阅读节点；坐标未确认时有明确回退；候选更新不重复、不抢占滚动位置。

## 8. M4：界面与生命周期回归

### 8.1 界面

正文为默认页；提供“图片识别”“原文对照”“诊断”入口。保留折叠截图预览、固定关闭按钮、拖动和完整滚动能力。诊断保留来源、边界、原因、错误及耗时，但默认正文不堆砌调试字段。头部显示实际版本以区分返测包。

正文中的 UNKNOWN/冲突/部分可见提示必须可见。用户切换卡片内入口、滚动、折叠原图，不应让页面身份变化，也不启动 OCR。隐藏/关闭 ImageView 后先解绑 Bitmap 引用，再交给资源所有者判断能否释放。

### 8.2 生产协调器必须满足的不变量

1. 逻辑取消立即拒绝旧结果；物理任务直到真实终止才释放占用。旧请求回调不能结束新请求。
2. 从“开始读取节点”起所有失败都有终止出口，包括节点异常、截图同步异常/失败/迟到、Bitmap 转换异常、OCR 启动异常/成功/失败/取消、窗口添加失败。
3. 底层尚未完成时再次点击返回 busy，不排无限任务、不超时清空占用。
4. 关闭、确定切页、锁屏或销毁后，新旧异步结果都不能重新打开窗口。任务失败后仍能再次主动识别。
5. Bitmap 必须同时满足 OCR 已终止、预览已解绑才释放一次。HardwareBuffer 各出口关闭一次；即使主线程显示任务已取消，迟到资源仍能清理。
6. OCR 完成早于 UI 建立时结果进入协调器快照，UI 建立后渲染；不能因 `previewJob` 还未赋值丢结果。
7. ML Kit 适配器明确唯一终止通知，处理成功、失败、取消和同步启动异常；若多个监听器可能到达则终止处理必须幂等。不能仅改测试标签假装覆盖分支。
8. 识别器/执行器在所有在途清理完成后关闭；不能关闭执行器而丢弃释放任务。不得用盲目 sleep 修竞态。
9. 渲染及候选操作前检查请求 ID、页面身份、锁屏、服务状态；只通过包名或窗口 ID 不足。

### 8.3 页面与事件

- 区分目标应用窗口和已确认的助手 overlay windowId/来源标记。仅包名相同、矩形相交或 source 为空都不足以确认事件来自卡片。
- 已确认卡片内部事件忽略；前台身份检查仍按需要执行。目标滚动/确定切页、锁屏、方向或窗口尺寸变化：使请求失效并清除旧卡片。
- 目标文字、contentDescription 或子树变化：立即使在途结果失效。已显示快照可保留但必须标“页面可能已变化，请重新取字”，禁用旧快照的纳入/替换操作；不得继续把旧结果当当前页面。确定离开/锁屏时仍清除。
- 不明确的相关事件保守标过期；无关事件忽略并给出可追溯原因。合成页与卡片同包时仍根据窗口/来源区分，不全包放行。
- 事件只维护元信息和过期状态，不读取后台正文，不自动 OCR。需要检查 source 时仅检查元信息，并释放引用，不遍历正文树。
- XML 订阅应覆盖实际使用的事件。前台多窗口、source 缺失、卡片创建引发窗口集合变化分别测试。无法确切区分的情况记录限制，不能靠长时间屏蔽所有事件保持卡片。

| T01 | 节点含花、爱心、颜文字、组合 Emoji、换行 | rawText 逐字一致，来源可回溯 |
| T02 | 同节点 text/desc 相同及冲突 | 相同可压缩，冲突双方不丢失 |
| T03 | 父子相同/部分相同且带独有符号 | 只压缩证实重复，独有内容保留 |
| T04 | 不同消息/位置同一句 | 两条均保留 |
| T05 | 无资源 ID、无集合信息、UNKNOWN | 回退可见，不猜分类，不丢内容 |
| T06 | 乱序 OCR 块、导航、语音时间、正文含时间 | 输出顺序稳定，不误删正文，不串消息 |
| T07 | 大容器覆盖图片、跨来源冲突/多重匹配 | 不因重叠丢 OCR，不自动覆盖节点 |
| T08 | 窗口偏移/缩放/方向变化/缺失边界 | 验证转换或显式禁用自动匹配 |
| T09 | 数量/深度/文本预算、部分屏外节点 | 限制提示；不把整段声明为完整可见 |
| T10 | 有效窗口节点为空、截图失败、OCR 失败 | 独立路径可读，状态和错误准确 |
| T11 | 取消后再点，底层未完成/已完成 | 前者 busy，后者可启动；旧结果拒绝 |
| T12 | 旧完成在新请求之后到达 | 新任务占用和 UI 不被解除/覆盖 |
| T13 | 销毁后截图迟到 | 不启动 OCR/UI，资源释放一次 |
| T14 | OCR 成功、失败、取消、启动异常 | 分别触发实际生产适配/协调路径，终止一次 |
| T15 | OCR 先完成、预览先关、窗口添加失败、回调晚到 | 结果不丢；资源仅在双方完成后释放一次 |
| T16 | 同包切页、锁屏、目标滚动、方向变化 | 页面失效；无旧结果回写 |
| T17 | 卡片滚动/切入口、source 缺失、同包测试页事件 | 真卡片事件不误取消，未知事件不盲目忽略 |
| T18 | 节点异常、截图同步异常、连续关闭、再次识别 | 没有永久 busy、重复释放或隐式重试 |
| T19 | OCR 更新到达时用户已滚动/选择 | 不重建窗口、不覆盖节点、不重置选择 |

纯 Java 测试调用生产 `TextAssembly`/`CaptureCoordinator`，注入受控截图、OCR、时钟、资源和显示端口。Android 适配器薄化但不能跳过真机检查；涉及 Bitmap、窗口、实际无障碍树的行为标为真机待测。扩展 `scripts/verify-probe-logic.ps1` 编译并运行所有新增入口；逐组输出断言结果和数量。NO-SOURCE、只测位置键、三个名称共用一个释放用例均不代表生命周期通过。

合成页使用自造文本，增加 text-only/desc-only、父子聚合、重复句、长文、部分可见、图片符号、导航/媒体/正文混排和异步内容变化。不要复制订阅正文、截图、设备序列号进入 Git。先完成桌面用例，再完成手机合成自测，最后做目标页面回归。

## 11. 官方资料与方案依据

以下资料在 2026-09-12 规划时查询。API 可用性以本项目锁定依赖和 minSdk 验证；以下整理规则是项目设计，不是官方保证。

- [AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo)：text/desc、父子关系、边界、集合项和可选 view ID。desc 可以描述容器/子树，所以不能无条件视为正文。
- [AccessibilityEvent](https://developer.android.com/reference/android/view/accessibility/AccessibilityEvent#getContentChangeTypes())：内容变化可区分文字、描述、子树等，适合细分过期策略。
- [窗口截图](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshotOfWindow(int,%20java.util.concurrent.Executor,%20android.accessibilityservice.AccessibilityService.TakeScreenshotCallback))：指定目标窗口截图可避免无障碍悬浮层覆盖。
- [ML Kit Text.Line](https://developers.google.com/android/reference/com/google/mlkit/vision/text/Text.Line)：行文字、边界、角点及置信度；置信度不能代替人工准确性验收。
- [ML Kit Android 输入建议](https://developers.google.com/ml-kit/vision/text-recognition/v2/android#input-image-guidelines)：字符需足够像素，盲目放大不保证增益；本轮保留原截图，后续预处理须做对照实验。
