## 8. 必须与已有代码合并的内容

### 8.1 数据模型不能长期并列

主工程已有 `capture.ProbeModels.Bounds` 和 `capture.ProbeModels.TextFragment`；交接包新增同概念的 `domain.model.Bounds` 与 `domain.model.TextFragment`。虽然包名不同、可以同时编译，但若两套模型长期并列，会造成坐标、来源、角色、置信度、provenance/warnings 和 selected 状态在转换中丢失。

后续必须选择清晰的唯一生产契约或建立单向、可测试的 Android 适配映射。不能直接批量替换 `ProbeModels`，因为现有服务、`TextAssembly` 和测试都依赖它，而且现有模型还保留交接模型没有的 `provenance`、`warnings`、`decisionReason` 等诊断字段。

### 8.2 `MessageAssembler` 必须接在“边界已确认”之后

交接包的 `MessageAssembler` 只接受 `boundaryConfirmed=true` 的 `ChatMessage`，并只组装 selected 且位于消息边界内的 BODY 片段。主工程当前只有整屏节点/OCR 候选和人工 OCR 勾选，没有已验证的消息边界检测器，也没有生产 `ChatMessage`。

因此不能把当前 `ProbeModels.Role.BODY` 直接转换成 `boundaryConfirmed=true`，也不能用 `MessageAssembler` 替换现有 `TextAssembly`。需要把已验证的边界规则或明确用户选择接入现有流程，并保留 UNKNOWN/媒体/OCR 候选及诊断证据。

### 8.3 页面身份必须合并到现有采集任务

`PageToken(targetPackage, windowId, pageEpoch, captureTime)` 与现有服务中的 `CaptureJob(requestId, packageName, windowId, pageEpoch, bitmap)` 概念重叠。后续应由现有采集开始点生成唯一 `PageToken`，并保证单调时间同毫秒的唯一性；不能另起一套页面状态源。

### 8.4 生命周期协调器必须收敛

生产服务目前使用 `ProbeLogic.RequestGate`，而新的 `CaptureCoordinator` 只存在于源码和测试。交接规则要求以现有 `CaptureCoordinator` 为迁移起点。下一阶段必须把请求占用、页面失效、关闭、截图/OCR 物理终止和结果展示逐项迁移到同一个协调器，并同步修改生产调用方与测试；在旧路径退役前不得让两者并行触发 OCR 或网络请求。

`TranslationProvider` 返回 `CompletionStage`，但其注释也承认取消 Stage 不保证底层 HTTP 停止。未来厂商适配必须把真实可取消句柄交给现有唯一协调器管理，不能因此创建第二套生产 `TranslationCoordinator`。

### 8.5 风格和翻译契约目前只能作为未激活能力

`StyleProfile`、`TranslationRequest/Result/Validator` 和 `SymbolProtector` 可以先作为纯 Java domain 与自测接入，但主工程目前没有：

- `StyleProfileRepository` 或用户可编辑风格存储；
- 消息边界和 authorId 的可靠来源；
- 翻译 Provider 实现、API Key 管理、HTTP 客户端或网络权限；
- 译文卡片状态、超时/重试及页面过期后的展示规则。

这些能力必须在正文门槛和唯一状态机合并后分阶段接入。不得用空壳或常量冒充已完成，也不得在本轮调用 DeepSeek。
