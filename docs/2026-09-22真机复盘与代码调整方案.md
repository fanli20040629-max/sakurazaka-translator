## 3. 全局约束

- 优先级：准确约等于美观，略高于翻译 API token 消耗，再高于响应速度。
- 本轮保持原生 Java/View，实现针对性修改；不因美化迁移 Compose/Flutter，不新增第二套翻译或分组系统。
- 自动预选不等于自动联网。仍由用户确认实际原文、风格后显式发送；不自动重试收费请求。
- 节点原文、换行、Emoji、波浪号保留原样。OCR 不覆盖节点，不凭文字长短或是否含日语就认定正文，不猜缺失表情。
- 复用 PageToken、单请求取消、迟到响应隔离；关闭、切页、锁屏之后不得复活旧结果。
- 附近显示只用当前有效的屏幕坐标；OCR 图像坐标不直接贴回屏幕。准确对应优先于显示数量。
- 不删除、忽略或削弱旧回归测试来制造通过；旧“默认不选”用例按模式拆分，新推荐模式另加验收。
- 日志不输出 Key、原文、译文、完整 XML 或截图。私有证据留测试机，公共仓库只存脱敏统计和合成样本。
- 本轮方案不授权推送、合并或改写 Git 历史。代码实现时保留原机签名、环境和未提交修改。

## 4. 源码查验与调整定位

以下路径均相对于仓库根；Java 简写 `capture/` 表示 `app/src/main/java/com/fanli/sakurazakatranslator/capture/`。

### 4.1 自动预选不能直接复用 BODY 标签

已确认：`TextAssembly.classify()` 先排除部分控件、媒体、时间格式及短可点击文本，剩余直接标记 BODY。普通人名、标题也可能成为 BODY；纯时间格式正文也可能被标成 METADATA。`CandidateSelection.open()` 清空选择；`CandidatePanel` 不设初始勾选。这是旧设计，非控件漏响应。

已确认：`MessageGrouper.selectionGroups()` 会把 BODY 候选暂时作为输入计算建议组，所以“分组建议只在手选后才产生”不够准确。真正翻译请求才使用实际已选集合。二者都不等于自动正文识别。

方案：新增 `capture/BodySelectionPolicy.java`，输出推荐 ID 及理由；它不修改原文、不发送请求。初版只实现可解释的结构规则，不增加云端分类和概率分数系统。

建议接口（待实现，不是现有 API）：

```java
public final class BodySelectionPolicy {
    public enum Decision { RECOMMEND, REVIEW, EXCLUDE }
    public record Assessment(String fragmentId, Decision decision, String reasonCode) {}
    public static List<Assessment> assess(
            List<ProbeModels.TextFragment> fragments,
            List<ProbeModels.NodeRecord> nodes,
            String targetPackage);
}
```

以上为接口约定示意，不是可直接编译粘贴的完整实现；具体规则必须依据下述条件与已核实样本编写。

推荐的必要条件：同一目标页面、节点可见且边界有效、无字段冲突或遍历截断；命中经过合成/真实样本验证的正文节点或消息容器结构；作者、时间、控件、媒体和页面标题已有独立区分证据。仅有 BODY 标签、位于列表中、包含日文或字符较多均不足以推荐。

优先验证 resource ID 与节点结构组合；不得编造资源 ID，也不得把单个偶像姓名写死当过滤器。若目标页没有稳定资源 ID，使用经过样本验证的父子层级与同级元数据结构；证据不足输出 REVIEW，明确告知仍需勾选。

`NODE_DESCRIPTION` 可能正是目标 App 的正文来源：若尚未验证则 REVIEW；若结构样本证明该字段仅承载正文，可推荐并保留来源证据，不应一律排除。图片节点描述混有朗读信息时不能自动当正文。

EXCLUDE 表示默认不选，仍允许用户追加纠正；不会从候选中删除。OCR 初版始终待核对。消息内的名字或“20:00”必须有可恢复的人工路径，不能做全局字符串删除。

### 4.2 附近显示的诊断与稳定回退

已确认：`BubbleTranslationOverlay.populate()` 把 Insets 缺失、视口无效、无可用锚点、测量超限、空间碰撞都归为零条。`show()` 又将 RuntimeException 转为零条，服务最后统一提示空间/位置不足。现有提示不能区分数据问题、正常回退和程序异常。

源码风险候选（不是本次真机已证实根因）：

- 有描述或可点击的大父容器被整体加入障碍集合，可能把实际留白一起封死。
- 第一轮布局已有尺寸但 Insets 尚未就绪时立即返回零条，可能过早回退。
- 默认测量宽度为 260dp，仅补一个较窄侧边宽度，且高度超过 200dp 或视口一半时放弃；长文回退是现有规则，不代表崩溃。
- 原卡片在计算前变为 INVISIBLE；只有成功、失败、取消与过期回调都一致收尾，才能避免用户看到无结果的空档。
- 目标原文进入安全视口必须完整可见；贴近边缘、部分截断的消息可能正常回退。

方案：

1. 用小型结果对象替换只有条数的回调，保留已放置 ID、回退 ID、整体状态及原因码。原因至少区分 `NO_SPACE`、`UNSAFE_ANCHOR`、`TEXT_TOO_TALL`、`GEOMETRY_NOT_READY`、`PAGE_STALE`、`WINDOW_ERROR`；不把异常描述当原始日志直接输出。
2. 保证同一次显示尝试只有一次最终完成回调。回调同时绑定 PageToken 和显示尝试标识；旧层的延迟回调不能关闭/恢复新层。
3. 几何未就绪只等真实 layout/insets 回调，最多 500ms 后明确回退；超时任务在关闭、成功和切页时取消，不循环重建窗口。这是待真机校准的初始上限。
4. 仅在已放置至少一条且页面有效后完成附近模式切换。确因测量需要先隐藏原卡片时，必须保证无放置、超时和异常路径恢复同一份完整译文；PAGE_STALE 清理旧结果并要求重新取字。
5. 在完整卡片内持续展示简短回退说明，不能只依赖一闪而过的 Toast。使用者看到“这页没有足够空白，译文保留在这里”等可理解描述，详细原因留诊断区。
6. 排查障碍集合时记录障碍数量、类别与面积占比。仅对证据确认的纯布局容器改为子内容障碍；文本叶子、媒体和实际可点击控件必须保留。未知大容器仍保守回退，不能直接删除所有父节点障碍以提高显示率。
7. 先修诊断和回退，再根据脱敏几何样本决定是否增加有限的测量宽度候选。每种宽度均重新测量完整文本；不缩小字号、不截断、不挤到另一条消息旁。

修改定位：`capture/BubbleTranslationOverlay.java`、`capture/BubbleLayout.java`、`capture/TranslatorAccessibilityService.java`、`capture/TranslationPanel.java`；布局回归放在 `tools/BubbleLayoutSelfTest.java`。仅在职责确实需要独立测试时抽出纯 Java 结果/障碍处理类。

### 4.3 候选卡事件与 ADB 操作

已确认：服务的候选卡使用 TYPE_ACCESSIBILITY_OVERLAY，只有 NOT_FOCUSABLE 与 LAYOUT_IN_SCREEN；没有 NOT_TOUCHABLE。附近译文层才明确不可触摸。不能据此提出“移除候选卡 NOT_TOUCHABLE”这种与源码不符的修复。

待验证：`activeApplication()` 只选 active 的 APPLICATION 窗口；交互时若活动窗口暂时变成浮窗，可能拿不到目标应用并清理预览。自身窗口 ID 登记时机、窗口切换事件、原页面变化也可能导致卡片提前关闭。当前只是假设，不能以加延时或忽略全部本应用事件解决。

方案：先给窗口创建/移除、active application 查询、页面失效入口加 debug 级事件摘要。记录单调时钟、事件类型、窗口 ID、页面世代、卡片矩形、显示模式和枚举关闭原因；不记录聊天内容。排错依据是同一次触摸中“卡片何时可见、触摸是否命中、谁先发出清理”。

ADB 每次根据新截图/节点边界确定命中位置，核实窗口存在且布局稳定后再操作；不复用旧固定坐标。第一次疑似穿透即停止该批点击，重新观察；未取得可靠卡片边界时转人工完成该项。需要脚本化时新增 `scripts/verify-device-interaction.ps1`，只做设备身份和状态采集，不包含无条件点击私聊或发送的命令。

若证实是 activeApplication 的盲点，再调整为“结合目标窗口身份、系统焦点和窗口类型判断前台”，不能无条件沿用最后窗口，也不能忽略目标页真实滚动/切换。若证实是坐标问题，仅修复操作脚本，不改生产触控策略。

### 4.4 推荐选择的接入

保持 `CandidateSelection` 为选择状态唯一来源，增补只读 `selectedIds()` 快照；已有 `open()` 默认空选保持手动模式含义。服务按顺序执行：

```text
读取节点 → 建立页面身份 → open() → BodySelectionPolicy.assess()
→ 同一 PageToken 下通过既有批量 setSelected() 应用 RECOMMEND 的 ID
→ 建立卡片 → 用 selectedIds 快照同步所有复选框和摘要
→ 用户核对 → 生成确认原文 → 显式发送
```

控件程序化同步时屏蔽监听回流，一次操作只更新一次模型/摘要。每次新采集只自动应用一次推荐；OCR 到达和布局刷新不得把用户已取消的正文重新选中。提供“全部取消”，保留整组和逐片段调整。

UI 展示“已推荐 X 个片段，Y 个待核对”；区分推荐数量、当前已选数量与确认后消息数量。未知项折叠但明确提示有待核对内容，不能隐藏遗漏风险。

修改定位：新增 `capture/BodySelectionPolicy.java`、`tools/BodySelectionPolicySelfTest.java`；修改 `capture/CandidateSelection.java`、`capture/CandidatePanel.java`、`capture/TranslatorAccessibilityService.java`、`tools/CandidateSelectionSelfTest.java`，以及 `tools/logic-sources.txt`、`tools/logic-test-classes.txt`。如需复用消息容器证据，从 `MessageGrouper` 提取最小共享方法，不复制整套分组算法。

### 阶段 D：真实链路、稳定性与视觉

- [ ] 阶段 B/C 达标后，在用户指定样本上少量调用已有 DeepSeek 文本链路；逐条检查消息 ID、中文、换行和符号。

通过标准：不得以附近零条回退通过“附近显示成功”。至少有一个受支持真实聊天样本证明中文确实靠近正确原文；若全部真实样本都无空间，则只能声明回退稳定，重新评估附近产品方案。

## 9. 翻译展示替代方案（用户追问后补充，待选定）

2026-09-22 已通过 Chrome 阅读 Google Translate 两份官方说明，借鉴的是交互方式，不是接入 Google 翻译 API，也不代表目标 App 已验证支持复制：

- [Translate text in other apps](https://support.google.com/translate/answer/6350658?hl=en&co=GENIE.Platform%3DAndroid)：可在其他应用内通过翻译浮窗处理复制的文字；该功能针对文字而非图片。
- [Translate images](https://support.google.com/translate/answer/6142483?hl=en&co=GENIE.Platform%3DAndroid)：支持图中选择文字、在卡片中显示译文、上拉查看长文，以及切换查看原文；官方同时说明模糊、小字号、风格化文字可能翻译不准确。

以下为结合本项目源码的设计建议，未实现，也未作为用户已同意的交互变更。

| 方式 | 使用体验 | 优点 | 代价与限制 | 建议 |
| --- | --- | --- | --- | --- |
| 现有气泡旁完整中文 | 在原日文附近同时显示若干完整译文 | 对应直观，短文体验自然 | 空白有限，密集/长文经常放不下；页面变化后坐标失效 | 保留为有空间时的增强展示 |
| 单条译文卡 + 原文定位提示 | 选一条消息，浮动卡只显示该条；可拖动、收起，切上一条/下一条 | 长短文都可读，窗口更少，最能复用现有代码 | 卡片仍占屏幕，不能声称零遮挡；选择标记需要可靠坐标 | 下一轮优先候选 |
| 底部可展开译文面板 | 底部一小块显示当前译文，展开后阅读全部 | 阅读稳定、单手操作容易；适合连续阅读与长文 | 覆盖底部原页面，不会自动把第三方页面向上挤；需收起/拖动和键盘避让 | 单条卡的停靠形态，不另建一套系统 |
| 冻结截图 + 双语阅读层 | 展示本次截图或原文片段，旁边/下方为可滚动中文 | 坐标固定、可重新排版、可按住/切换看原图 | 阅读的是截取时刻，不是实时聊天；操作后要返回原页；受截图权限限制 | 长文/密集页的第二阶段方案 |
| 遮盖日语、原位置填中文 | 看起来像原 App 已汉化 | 最接近原位替换外观 | 中文尺寸不同，可能压缩文本或遮住 Emoji/图片，背景修复和误对应风险较高 | 暂不作为默认路线 |

推荐组合：短文且有可靠空白时保留附近全文；否则用单条译文卡，默认靠底部、可拖动和收起。正文自动选择解决“选哪些文字翻译”；选择当前要读的译文解决“展示哪一条”，两者要分清，后者不重新收费。

建议交互顺序：用户点击取字入口 → 推荐正文并允许调整 → 显式确认翻译 → 中文阅读卡展示结果 → 点击卡片内的编号或上一条/下一条切换；坐标可靠时轻量提示对应原文。第一版优先通过卡内控制选择，不先实现覆盖整个原 App 的透明点击拦截层。若未来加原文旁可点标记，其触控窗口应仅占标记自身区域，不能阻碍整页滚动。

定位提示必须与 PageToken 绑定。原页滚动、切换、窗口尺寸变化后，先撤销定位；初版沿用当前清理策略，不承诺边滚动边追踪。若之后允许保留旧译文供阅读，必须明确标为“上次识别结果”，不能继续显示旧位置对应标记。

截图阅读层可以继续复用节点原文和已有译文；只有需要补识别时才引入 OCR/视觉模型。把截图显示在本地不等于必须上传图片，更不应为了改变展示而重新调用翻译模型。默认截图驻留内存、关闭释放，不引入聊天历史持久化。

若用户选择单条阅读卡方案，调整阶段 D：先将 `TranslationPanel` 中已验证的结果呈现部分整理为可复用视图，服务管理一个阅读窗口；选择页与阅读页职责分离，复用同一份 TranslationRequest/TranslationResult。不要同时保留两套重复的编号映射、请求和状态控制。

额外验收：中文/原文一一对应；长文可完整滚动；卡片可收起和移动；展开不触发底层消息点击；面板外的目标页正常操作；键盘区域不遮挡关键控件；重复切换不增加请求；截图模式明确提示当前是静态截取，不伪装实时页面。视觉配色和圆角最后统一，原文符号保真不能因排版改变。
